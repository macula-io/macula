# App record, macula 13: the vectors

The contract every Macula SDK implements for app records (macula#75): an org's signed statement of one of its apps,
stored under the app's MRI, carrying the realm-signed org directory that authorizes the org. The record is described in
`docs/design/DESIGN_PQ_SIGNED_FRAMES_AND_RECORDS.md`, "App records". The reference implementation is
`macula_record:app_record/5`, `verify/3`, `verify_app/3`, `read_app_record/1` and `app_key/3`. `app_record_v1.json`
holds the vectors, generated by `scripts/generate-app-record-vectors.sh` from `macula_record` itself, and
`test/macula_app_record_vectors_tests.erl` re-derives every outcome from the file on each run.

ML-DSA-87 signing is hedged and pq_hybrid's RSA-PSS half is randomized, so running the generator again signs other
records with the same outcomes. The committed file is the vector.

## What an SDK must pass

For each profile (`pq_pure`, `pq_hybrid`):

1. `app_key(realm_id, "acme", "weather")` is the profile's `app_key`, where `realm_id` is sha256 of the file's
   `realm_name`.

And for each case, at the case's `now_ms`:

2. Verifying `record` (hex of the wire form) under the profile gives `verify`: `ok`, or the refusal named (`malformed`
   for a payload that breaks the app record's shape rules, `expired` past its lifetime).
3. When it verifies, the app check against the profile's `realm_key` (the realm key as carried, hex) gives
   `verify_app`: `ok`, `org_key_mismatch`, `org_directory_wrong_realm`, `org_directory_wrong_org` or
   `authorization_outlived`. It is `null` when the record did not verify.
4. When it verifies, reading it gives `reading`: `realm_id`, `org_key` as hex, `org_name`, `app_name` and `version` as
   text, `services` as a list of `name` and `procedures`, and `org_directory_sha256`, the sha256 (hex) of the carried
   org directory's wire form. It is `null` when the record did not verify.

## The cases

| Case | verify | verify_app |
|---|---|---|
| `valid` | ok | ok |
| `directory_names_another_org_key` | ok | org_key_mismatch |
| `directory_from_another_realm_key` | ok | org_directory_wrong_realm |
| `directory_for_another_org` | ok | org_directory_wrong_org |
| `outlives_directory` | ok | authorization_outlived |
| `expired` | expired | null |
| `node_namespace_org` | malformed | null |
| `foreign_namespace_procedure` | malformed | null |
| `duplicate_service_name` | malformed | null |
| `version_past_64_bytes` | malformed | null |

The four malformed records were signed by hand, as a hostile org could: a builder refuses to make them, and a
verifier must refuse them too.
